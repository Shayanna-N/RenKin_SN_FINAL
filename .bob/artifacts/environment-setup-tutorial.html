Environment Setup Tutorial

How to configure the required environment variables for this Next.js networking app.

What you need

Variable Required? Purpose
AI_GATEWAY_API_KEY Required Powers all 3 AI agent routes (Scribe, Doer, Companion) via Vercel AI Gateway
DATABASE_URL Required PostgreSQL connection string for contacts, sessions, and user data
BETTER_AUTH_SECRET Required Secret key used by better-auth to sign sessions and tokens
BETTER_AUTH_URL Optional Base URL for auth callbacks. Auto-detected from Vercel env vars if omitted.
1
Create your .env.local file

At the root of the project (next to package.json), create a file called .env.local. This file is already listed in .gitignore so it will never be committed.

# .env.local — never commit this file

AI_GATEWAY_API_KEY=your_key_here
DATABASE_URL=postgresql://user:password@host:5432/dbname
BETTER_AUTH_SECRET=a_long_random_string

# Only needed if not running on Vercel
BETTER_AUTH_URL=http://localhost:3000
⚠️ Never use real values in examples shared with others. Keep this file local only.
2
Get your AI_GATEWAY_API_KEY

This app routes all AI calls (openai/gpt-4o-mini, openai/gpt-5.4-mini) through the Vercel AI Gateway.

  • Go to vercel.com → your team → Settings → AI
  • Under AI Gateway, generate an API key
  • Paste it as the value of AI_GATEWAY_API_KEY
ℹ️ If you're running locally and don't want to use AI Gateway, you can swap the model strings in the route files to use a direct provider (e.g. openai('gpt-4o-mini') with OPENAI_API_KEY set), but that requires editing the route files.
3
Set up DATABASE_URL

The app uses a PostgreSQL database (via pg pool in lib/db/index.ts) for user accounts and contact data.

  • Local: install Postgres and create a database, e.g. createdb networking, then use postgresql://localhost/networking
  • Vercel Postgres: add the Vercel Postgres integration to your project — it auto-populates DATABASE_URL in the Vercel environment
  • Neon / Supabase / Railway: copy the connection string from the dashboard
DATABASE_URL=postgresql://user:pass@localhost:5432/networking

After setting this, run the better-auth migration to create the required tables:

npx @better-auth/cli migrate
4
Generate BETTER_AUTH_SECRET

This must be a long, random string. Generate one with any of these:

# Node.js
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# OpenSSL
openssl rand -hex 32

# Or use the better-auth CLI
npx @better-auth/cli secret

Paste the output as the value of BETTER_AUTH_SECRET.

5
Start the dev server

Once your .env.local is populated, start the app normally:

pnpm dev

Next.js automatically loads .env.local — no extra tooling needed.

ℹ️ If you see "AI_GATEWAY_API_KEY missing" errors in the console, double-check the variable name is exactly AI_GATEWAY_API_KEY with no extra spaces or quotes.
6
Deploying to Vercel

.env.local is only for local development. For production, add the variables in the Vercel dashboard:

  • Go to your project → Settings → Environment Variables
  • Add AI_GATEWAY_API_KEY, DATABASE_URL, and BETTER_AUTH_SECRET
  • BETTER_AUTH_URL is not needed on Vercel — it's auto-detected from VERCEL_PROJECT_PRODUCTION_URL
⚠️ Set DATABASE_URL for the Production environment only, unless you want preview branches to share the same database.
